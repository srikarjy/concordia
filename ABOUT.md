# About

## The problem

Explainability in medical-imaging AI usually means one saliency map next
to one prediction. That map is generated by the same model being
explained, using the same weights, the same biases, and the same
blind spots — it can look convincing and still be telling you nothing
true about why the model actually decided what it decided. And the
"confidence score" sitting next to it is almost never checked against
whether high-confidence predictions are in fact more often correct.

Concordia starts from a different premise: a single explanation method
proves it can explain itself, not that it's right. Confidence in a
diagnostic tool should come from **agreement across independent
methods**, and every claim about confidence should be **measured**, not
asserted.

## The approach

Three explanation layers that don't share assumptions:

1. **Intrinsic** — ConceptCLIP's own region-concept alignment, computed
   for the top candidate concepts so a "differential" call has real
   comparable evidence, not just a runner-up label.
2. **Structured trace** — the intrinsic output organized into a primary
   finding, supporting/competing evidence, the score-margin basis for the
   confidence tier assigned, and a counterfactual (what would need to
   change for a different verdict).
3. **Post-hoc cross-validation** — LIME and SHAP, which perturb the image
   and watch the score move. They know nothing about "concepts"; they're
   a check from outside the model's own vocabulary.

A **concordance score** quantifies how much the three agree on where the
evidence is. High agreement plus a correct label is a genuinely trustworthy
result. High confidence with low concordance is exactly the case a human
reviewer should see flagged, not hidden behind a single clean-looking
heatmap.

None of this is worth anything without a check against ground truth —
which is why the evaluation harness (calibration, per-tier accuracy,
concordance-vs-correctness) is treated as core functionality, not a
follow-up nice-to-have.

## Why this is a portfolio project, not a product

This isn't a clinical tool and isn't claiming diagnostic accuracy. It's a
demonstration of how to build a diagnostic-support system whose confidence
and explanation claims are actually falsifiable — the kind of rigor that
matters more in high-stakes ML than another few points of top-1 accuracy.
