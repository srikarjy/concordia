## Concrete changes in this session

- Added `tests/unit/test_t2_artifact_provenance.py`: 17 tests covering all five
  required areas. Revision tests monkeypatch `snapshot_download` and assert the
  pinned `revision`, `repo_id`, and `allow_patterns` actually reach it, that a
  snapshot resolving outside the declared commit is refused, and that a
  substituted weight digest is refused — no model is downloaded. Asset tests
  install a small synthetic manifest and re-pin the trusted digest, then cover
  the accepted path, a tampered manifest, a missing file, a tampered file of
  equal size, a truncated file, and a path escaping the asset root. An ordering
  test asserts `verify_assets` precedes `joblib.load` in the engine
  constructor, and a source test asserts initialization contains no
  recalibration or write call. Supplied-metric and execution-artifact tests
  assert a rules-passing caller payload stays ineligible for scientific use and
  that a structure claim without a stored execution artifact is not SUPPORTED.
  All fixture bytes carry `test_only` / fixture labels.
- Fixed `src/concordia/runtime/esm_checkpoint.py`: `allow_patterns` was passed a
  tuple where `snapshot_download` accepts `list[str] | str | None`. This is a
  real API-contract defect, not only a typing complaint.
- Fixed `src/concordia/verification/cross.py`: the `assess_only` branch inferred
  `tuple[()]`, so the three provenance locals could not hold results.
- Fixed `src/concordia/stability/assets.py`: `json.loads` returned `Any` from a
  function declared `dict[str, Any]`; the manifest is now explicitly rejected
  when it is not a JSON object.

The three fixes are minimal and change no scientific output. Without them
`make typecheck` — a blocking check — failed on the inherited tree.

## Remaining limits

1. **T1's fresh-clone blocker is unchanged.** Six frozen 1IGV files remain
   gitignored and unavailable from Git alone. `verify_assets` proves the local
   bytes are the approved bytes; it does not distribute them or license
   redistribution. `distribution_status` in the manifest still reads
   `local_verified_bytes_only_no_public_bundle`. CI cannot run the real
   scientific regressions until that is solved.
2. The asset tests deliberately use small synthetic fixtures with a re-pinned
   trusted digest. They verify the *logic* of size, digest, traversal, and
   ordering checks. The only test that touches the real manifest reads and
   hashes that one 47-line JSON file; no test hashes the 121 MB CSV.
3. The revision tests stub `snapshot_download`. They prove the loader *requests*
   the pinned commit and rejects a mismatched resolution. They do not prove the
   upstream repository still serves that commit, and no real ESM-2 weight bytes
   were fetched or verified in this session.
4. No scientific claim is established here. Nothing in T2 validates ThermoMPNN
   parity, predictor performance, IG feasibility, or biological correctness.
   T3's protocol gates all remain unrun, and the `thermompnn_leakage` audit gap
   T3 recorded is untouched.
5. Docker, Linux deployment lockfiles, GPU runtimes, live Postgres, Supabase
   authentication, hosted providers, and the browser suites were not exercised
   in this session. T1's recorded browser results were not re-run.
