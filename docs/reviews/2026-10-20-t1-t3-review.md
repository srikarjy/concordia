## Blocking findings

### R1 — Execution presence does not establish the claimed execution

Location: `src/concordia/verification/cross.py`, `check_provenance`, around
lines 203–223 in the reviewed commit.

The check accepts an execution if two referenced blobs exist. It does not
require successful terminal status or bind the request/response to the claimed
input, model, settings, or derived evidence. A source-sequence path and execution
can be on separate branches.

Bounded reproducer:

1. Store source sequence A and unrelated sequence B as eligible envelopes.
2. Store an execution whose request names B and a different model, whose
   response says `status="failed"`, and whose dependency is B.
3. For each evidence envelope, attach A and that execution as sibling parents.
4. Supply otherwise passing structure measurements for a claim about A.

Observed: `status="SUPPORTED"`, `scientific_use_allowed=true`, `reasons=[]`.
All reproducer bytes were artificial review fixtures.

Also observed: an execution payload containing JSON `[]` raises uncaught
`AttributeError: 'list' object has no attribute 'get'`.

Remedy: typed execution validation, terminal success and identity checks,
explicit input → execution → output → derived evidence relationships, and
structured rejection for malformed payloads. Cover unrelated, failed,
malformed, and valid retained paths in regression tests. Hash validity alone
must not be described as source authenticity or biological validity.

### R2 — Cache reuse assigns an unverified checkpoint identity

Location: `scripts/evaluate_tsuboyama_predictor.py`, `load_or_extract`, around
lines 110–121.

A Parquet cache with the expected variant-ID set is returned with the currently
configured checkpoint and commit. No recorded source identity or cache digest
is checked on this path. Pinning the fresh loader does not repair this path.

Bounded reproducer: create a temporary Parquet file containing one synthetic
variant ID and `f0=12345.0`; point `EMBEDDING_CACHE` to it; request that variant;
stub fresh extraction to fail if called.

Observed: the arbitrary value was accepted and metadata asserted
`facebook/esm2_t33_650M_UR50D` at
`08e4846e537177426273712802403f7ba8261b6c`, without executing the loader.

Remedy: validate cache content and persisted provenance against the requested
sequence/variants/features/checkpoint. Do not retrofit known model identity
onto historical caches without evidence. This finding concerns the evaluation
cache path; the serving engine's new pinned manifest is a separate protection.

### R3 — Clean Git snapshot cannot run required scientific regressions

Locations: `.github/workflows/ci.yml` asset preflight steps,
`scripts/check_stability_assets.py`, and
`data/manifests/tsuboyama_stability_assets_v1.json`.

A temporary extraction of `git archive HEAD` failed the preflight with six
missing scientific files. Comparing the full serving manifest found seven
missing files because calibration is also required but absent from that
preflight list.

The missing inputs are the ensemble, embeddings, ranker, calibration,
uncertainty metrics, normalized table, and structure. No acquisition step
precedes the CI preflight.

Remedy: a permitted, verified asset acquisition/preparation path, complete
manifest-driven checks, and a test using a clean checkout. Preserve required
tests and historical outputs. Local asset availability does not close this
release blocker. This was already acknowledged in T1/T2, not newly introduced
by the final T2 test commit.

### R4 — Static replay exports a different revision from the displayed one

Location: `frontend/src/review-main.tsx`, `replayFiles` / `exportLink`, around
lines 85–86; static artifacts under `frontend/public/review-replay/`.

Every replay revision links the same final CSV/HTML/ZIP files. Revision 1 has
no selected candidates; `selected.csv` contains selected candidate K6Q with
`review_revision=7`. The UI describes exports as belonging to the current
revision. The replay test switches to revision 1 but checks only download
HTTP status, so it passes despite the mismatch.

Remedy: revision-specific exports, or clearly labeled final-only downloads
restricted appropriately. Assert downloaded contents and revision identity.
This behavior is inherited in the replay workflow, not solely authored by T1,
but it affects the portfolio's visible replay/export promise.
